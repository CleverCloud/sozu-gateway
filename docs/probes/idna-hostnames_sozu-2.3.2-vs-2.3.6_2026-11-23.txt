# b3c946c6) change which frontend hostnames the main process accepts, as an exhaustive
# `idna::domain_to_ascii` diff over both data sets predicted? Every name in
# crates/builder/tests/hostnames.rs is re-checked on both versions too.
# Method: a fresh `docker run --network host --user 1000:1000 clevercloud/sozu:<v> start` per version,
# 1 worker, one HTTP listener on 127.0.0.1:35080, the socket directory bind-mounted from the host; one
# `sozu cluster add --id c --load-balancing-policy round_robin`, then one
# `sozu frontend http add --address 127.0.0.1:35080 --hostname <name> id c` per name, through the
# image's own CLI (`docker exec`). Each line is the name and the CLI's output, its log banner kept.
# Images: clevercloud/sozu:2.3.2 @sha256:273fc58803618c3707f817ca772ca537714f22fcb10416f263246352b47ca7e3,
#         clevercloud/sozu:2.3.6 @sha256:27a14a59900be6b234766692b3bf0c2629e17e3a85d69f08532bf928d5543841.
# Names: U+18E00 (xn--pc7f, Jurchen), U+12550 (xn--zg5d), U+1DB00 (xn--wf3h) are unassigned in Unicode 17
# and assigned in 18; xn--4db870i is U+05D0 U+1B3A and xn--mgb409h is U+0627 U+1B3A, a right-to-left label
# holding a Balinese vowel sign whose Bidi_Class moves from NSM to L in Unicode 18. The rest are the
# fixtures of hostnames.rs and of the builder's hostname_tests.
